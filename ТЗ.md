# Техническое задание на разработку приложения «ПослеЛекции»

## 1. Цель проекта

Создать приложение, которое делает пост-лекционный опрос коротким, честным и полезным:

- **для студента** — быстрая самопроверка сразу после лекции и возможность отметиться;
- **для преподавателя** — аналитика понимания материала, обратная связь о лекции и учёт посещаемости без ручного сбора;
- **для вуза** — данные о вовлечённости студентов, качестве преподавания и посещаемости лекций.

Ключевой принцип: **опрос не влияет на оценки**. Это инструмент самопроверки, обратной связи и учёта посещаемости, а не контроль.

---

## 2. Область применения и платформы

| Компонент | Платформа | Основной пользователь |
|---|---|---|
| **Мобильное приложение** | Android / iOS (кросс-платформенная разработка) | Студент |
| **Веб-версия** | Браузер (адаптивная вёрстка) | Преподаватель |
| **Бэкенд** | Серверное приложение с REST API | Система |

> **Решение по платформам:** интерфейс преподавателя проектируется в первую очередь как веб-версия для компьютера — именно там удобно загружать материалы, настраивать опрос и смотреть аналитику. Интерфейс студента — мобильное приложение, так как основной сценарий (пройти опрос после лекции) происходит со смартфона.

---

## 3. Термины и определения

| Термин | Определение |
|---|---|
| **Лекция** | Событие с названием, описанием, датой и прикреплёнными материалами |
| **Материал** | Текст, прикреплённый к лекции |
| **Опрос** | Набор параметров для генерации вопросов (количество, типы, дедлайн, инструкция преподавателя) |
| **Диалог** | История общения студента с ИИ-ботом по конкретной лекции, включая возможный комментарий преподавателя в конце диалога |
| **Обратная связь** | Оценка лекции и комментарии студента |
| **Саммари** | ИИ-обобщение для преподавателя: отдельно по ответам студентов на вопросы и отдельно по обратной связи о лекции |

## 4. Функциональные требования

### 4.1. Роли пользователей

Система поддерживает две роли:

- **Студент** — проходит опросы, получает обратную связь, отмечается на лекции.
- **Преподаватель** — создаёт лекции, настраивает опросы, смотрит аналитику, комментирует диалоги студентов.

Разграничение доступа — на уровне ролей. Один пользователь имеет одну роль.

### 4.2. Авторизация и регистрация

| ID | Требование |
|---|---|
| AUTH-1 | Регистрация по email и паролю с выбором роли (студент / преподаватель) |
| AUTH-2 | Вход по email и паролю |
| AUTH-3 | Выход из аккаунта |
| AUTH-4 | Восстановление пароля через email |
| AUTH-5 | Хранение пароля в виде хеша |

### 4.3. Модуль преподавателя (веб-версия)

#### 4.3.1. Управление лекциями

| ID | Требование |
|---|---|
| T-LEC-1 | Создание лекции: название, описание (необязательное), дата |
| T-LEC-2 | Редактирование и удаление лекции |
| T-LEC-3 | Прикрепление материалов: текст |
| T-LEC-4 | Просмотр списка своих лекций |

#### 4.3.2. Настройка опроса

| ID | Требование |
|---|---|
| T-QUIZ-1 | Настройка количества вопросов |
| T-QUIZ-2 | Выбор типов вопросов: тест с одним вариантом, тест с несколькими вариантами, короткий развёрнутый ответ |
| T-QUIZ-3 | Указание текстовой инструкции для ИИ (необязательно) |
| T-QUIZ-4 | Настройка дедлайна прохождения |
| T-QUIZ-5 | Генерация кода доступа к опросу |
| T-QUIZ-6 | Открытие / закрытие опроса вручную |

#### 4.3.3. Мониторинг и аналитика

| ID | Требование |
|---|---|
| T-AN-1 | Просмотр количества студентов, прошедших опрос, в реальном времени |
| T-AN-2 | Просмотр ИИ-саммари по ответам студентов на вопросы лекции (насколько успешно отвечают, какие аспекты лучше или хуже) |
| T-AN-3 | Просмотр списка диалогов студентов с ИИ-ботом |
| T-AN-4 | Просмотр ИИ-саммари обратной связи |
| T-AN-5 | Просмотр базовых графиков: посещаемость, средний уровень понимания |
| T-AN-6 | Добавление комментария преподавателя в конец диалога студента |

### 4.4. Модуль студента (мобильное приложение)

| ID | Требование |
|---|---|

| S-CHAT-1 | Чат-интерфейс с ИИ-ботом (сообщения, вопросы, ответы) |
| S-CHAT-2 | Ответ на вопрос в формате теста (один или несколько вариантов) |
| S-CHAT-3 | Ответ на вопрос в формате короткого текста |
| S-CHAT-4 | Получение мгновенной обратной связи после ответа |
| S-FB-1 | Заполнение обратной связи о лекции |
| S-FB-2 | Без прохождения блока обратной связи опрос не считается завершённым |
| S-RES-1 | Просмотр итоговой справки по результатам опроса |
| S-HIST-1 | Просмотр истории своих диалогов по лекциям |
| S-COMM-1 | Просмотр комментария преподавателя в конце диалога |

### 4.5. ИИ-модуль

| ID | Требование |
|---|---|
| AI-1 | Генерация вопросов по материалам лекции через LLM API |
| AI-2 | Уникальный набор вопросов для каждого студента (или случайная выборка из пула) |
| AI-3 | Проверка коротких развёрнутых ответов по смыслу (не по шаблону) |
| AI-4 | Формирование мгновенной обратной связи студенту |
| AI-5 | Формирование двух ИИ-саммари для преподавателя: по ответам студентов на вопросы лекции и по обратной связи о лекции |

> **Ограничение:** используется внешний LLM API.

|---|---|

## 6. Критерии приёмки

### 6.1. Авторизация

- При корректных данных вход успешен и открывается главный экран соответствующей роли.
- При нагрузке 50 одновременных пользователей среднее время ответа API для `/login` ≤ 2 секунд.

### 6.2. Преподаватель

- Преподаватель может создать лекцию, прикрепить текст и сгенерировать код доступа.
- После генерации опроса ИИ выдаёт заданное количество вопросов по материалам лекции.
- Преподаватель видит в реальном времени число студентов, прошедших опрос.
- После закрытия опроса преподаватель видит: посещаемость, средний уровень понимания, два ИИ-саммари.
- Преподаватель может добавить комментарий в конец диалога студента.

### 6.3. Студент

- Студент может войти в опрос по коду и пройти чат-опрос.
- После каждого ответа студент получает обратную связь.
- Без прохождения блока обратной связи опрос не считается завершённым.
- В конце студент видит итоговую справку по результатам опроса.
- Студент может просмотреть комментарий преподавателя в конце своего диалога.

### 6.4. ИИ

- Вопросы генерируются на основе загруженных материалов и соответствуют теме лекции.
- Короткие развёрнутые ответы проверяются по смыслу, а не по точному совпадению.
- Формируются два ИИ-саммари для преподавателя: по ответам студентов на вопросы и по обратной связи о лекции.

### 6.5. Бэкенд

- Все данные сохраняются и доступны после перезапуска сервера.
- API возвращает корректные коды ответов (200, 400, 401, 403, 404, 500).
- Разграничение доступа работает: студент не может получить доступ к аналитике преподавателя.

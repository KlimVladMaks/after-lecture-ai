# Техническое задание на разработку приложения «ПослеЛекции»

**Версия 2.0.** Актуальная редакция ТЗ. Основной документ проекта: единственный источник требований для проектирования интерфейсов, архитектуры и API.

Учебный проект по дисциплине «Проектирование мобильных и сетевых приложений» (ИТМО). Документ фиксирует требования к продукту; выбор технологий, схема данных и спецификация API определяются на следующих этапах. Обоснования и история решений в документ не включены.

**Соглашения по идентификаторам:**

- `AUTH`, `T-LEC`, `T-QUIZ`, `T-AN`, `S-*`, `AI`, `BE` — функциональные требования (42 шт., сохранены из исходного ТЗ);
- `NF-1…NF-6` — нефункциональные требования;
- `BR01…BR06` — бизнес-правила; `UC01…UC11` — сценарии использования; `AC01…AC12` — проверки будущего продукта;
- `P01…P09` — открытые вопросы: **предложено, не утверждено**. Метка `[P0x]` в тексте означает, что поведение требует согласования с заказчиком; до согласования действует предложение по умолчанию из §13.

## 1. Цель и ключевой принцип

Сделать пост-лекционный опрос коротким, честным и полезным:

- **студенту** — быстрая самопроверка сразу после лекции, обратная связь по каждому ответу и отметка об участии;
- **преподавателю** — аналитика понимания материала, отзывы о лекции и учёт посещаемости без ручного сбора;
- **вузу** — агрегированные данные о вовлечённости студентов и качестве преподавания.

**Ключевой принцип: опрос не влияет на учебные оценки.** Это инструмент самопроверки, обратной связи и учёта участия, а не контроль. Низкий результат не превращает завершённый опрос в незавершённый.

## 2. Границы проекта

**Входит:**

- мобильное приложение студента (Android / iOS);
- адаптивная веб-версия преподавателя, в первую очередь для компьютера;
- сервер с REST API, хранением данных, токенной аутентификацией и проверкой прав;
- внешний LLM API: генерация вопросов, проверка коротких ответов, объяснения, два саммари;
- push-уведомление студенту о комментарии преподавателя.

**Не входит:** роль администратора и кабинет вуза, межкафедральная отчётность; интеграции с ИСУ и my.itmo; загрузка PDF, презентаций и аудио (только текст); прохождение опроса офлайн; смена и объединение ролей; подтверждение статуса преподавателя вузом; геолокация и проверка личности студента.

Для примеров и демонстраций используются только вымышленные данные.

## 3. Платформы и компоненты

| Компонент | Платформа | Основной пользователь |
|---|---|---|
| Мобильное приложение | Android 10+ / iOS 14+, кросс-платформенная разработка | Студент |
| Веб-версия | Chrome, Firefox, Safari последних версий; адаптивная вёрстка | Преподаватель |
| Бэкенд | Серверное приложение, REST API | Система |
| Внешний LLM API | HTTP-сервис | Система |

Основной сценарий студента происходит со смартфона сразу после лекции; преподавателю удобнее компьютер — загрузка материалов, настройка опроса, аналитика.

## 4. Роли и права доступа

Один аккаунт — одна роль, выбирается при регистрации.

| Участник | Разрешено | Запрещено / ограничено |
|---|---|---|
| Без входа | Регистрация, вход, восстановление пароля | Любые лекции, диалоги, аналитика |
| Студент | Вход по коду, прохождение опроса, отзыв, итоговая справка, своя история, комментарии преподавателя | Редактирование лекций и опросов; чужие диалоги и аналитика |
| Преподаватель | Управление своими лекциями и опросами, участники, аналитика, диалоги, комментарии | Лекции и данные другого преподавателя; прохождение студенческого сценария |
| LLM API, сервисы email и push | Обработка данных в рамках одной операции, доставка сообщений | Не пользовательские роли, не влияют на права доступа, не получают доступ ко всей базе |

**Правило доступа:** проверяется роль **и** принадлежность объекта. Знание идентификатора чужой лекции или диалога доступа не даёт. Идентификация участника — внутренний ID аккаунта и email; ФИО, учебные группы и списки контингента не предусмотрены.

## 5. Термины

| Термин | Определение |
|---|---|
| Лекция | Событие: название, необязательное описание, дата, автор, текстовые материалы |
| Материал | Текст, прикреплённый к лекции; основа генерации вопросов |
| Опрос | Настройки вопросов (количество, типы, инструкция ИИ), дедлайн, код доступа, состояние |
| Попытка | Прохождение опроса конкретным студентом: набор вопросов, ответы, прогресс, статус |
| Диалог | История вопросов, ответов и объяснений ИИ по лекции; комментарий преподавателя — в конце |
| Обратная связь ИИ | Объяснение результата конкретного ответа студенту |
| Отзыв о лекции | Оценка лекции и комментарий студента; отдельный блок после вопросов |
| Итоговая справка | Результаты самопроверки и пояснения по завершённому опросу, без учебной отметки |
| Саммари | ИИ-обобщение для преподавателя: отдельно по ответам на вопросы и отдельно по отзывам |
| Посещаемость в приложении | Показатель участия по завершённым попыткам; присутствие в аудитории само по себе не доказывает |

## 6. Бизнес-правила

| ID | Правило |
|---|---|
| BR01 | Правильность ответов не влияет на учебные оценки и не может сделать завершённый опрос незавершённым |
| BR02 | Опрос завершён только после ответов на вопросы **и** отправки блока отзыва; ответы без отзыва не увеличивают счётчик завершивших |
| BR03 | Студент видит только свои диалоги, преподаватель — диалоги участников своих лекций; саммари по ответам и по отзывам формируются и показываются раздельно |
| BR04 | Код связывает студента с конкретным опросом, но не заменяет вход и проверку прав; доступ ограничен дедлайном, состоянием опроса и ручным закрытием |
| BR05 | Вопросы генерируются только по материалам лекции и допустимой инструкции преподавателя; количество и типы соответствуют настройкам |
| BR06 | Данные сохраняются после перезапуска сервера; ошибка сети или ИИ не отображается как сохранённый ответ или завершённый опрос; повтор запроса не создаёт дубль |

## 7. Состояния объектов

**Опрос:** `Черновик → Подготовка → Открыт → Закрыт`.

- «Подготовка» — ожидание готовности вопросов; при ошибке ИИ опрос остаётся недоступным студентам, показывается причина и возможность повторить подготовку.
- Переход в «Открыт» возможен только при валидных материалах, настройках и полном наборе вопросов.
- «Закрыт» — по дедлайну или вручную: новые попытки и новые ответы не принимаются, история доступна для чтения.

**Попытка:** `Не начата → В процессе → Ожидает отзыва → Завершена`, либо `Не завершена к закрытию`.

- Ожидание проверки ИИ — промежуточное состояние ответа, а не успешное завершение.
- После последнего проверенного ответа открывается отзыв; успешная отправка обязательных полей завершает попытку **один раз**.
- Набор вопросов закрепляется за попыткой и не меняется при возврате; повторный вход продолжает сохранённую попытку.
- Детали возобновления, дедлайна и числа попыток — `[P06]`; момент зачёта участия — `[P01]`.

## 8. Сценарии использования

| ID | Сценарий | Основной поток и результат | Ошибочные ветки |
|---|---|---|---|
| UC01 | Регистрация, вход, выход | Email и пароль, при регистрации одна роль → открывается интерфейс роли. Выход завершает сеанс | Неверные данные, повторный email, недоступность сервера: остаёмся на экране входа, сообщение на русском |
| UC02 | Восстановление пароля | Email → подтверждение → новый пароль → вход | Неверное, просроченное или использованное подтверждение не меняет пароль; ответ не раскрывает наличие аккаунта |
| UC03 | Подготовка лекции | Создание лекции (название, дата, описание), прикрепление текста → лекция в своём списке, редактирование, удаление с подтверждением | Без обязательных полей сохранения нет; пустой материал не годится для генерации; чужая лекция недоступна; удаление с ответами — `[P08]` |
| UC04 | Настройка и открытие опроса | Количество, типы, дедлайн, инструкция → система готовит вопросы → код доступа → открытие | Неверное количество, отсутствие типов, истёкший дедлайн требуют исправления; ошибка ИИ — причина и повтор; неполный набор не открывается |
| UC05 | Подключение и возврат к опросу | Ввод кода → проверка кода, состояния и серверного времени → показ лекции и попытки | Неизвестный код, закрытый опрос и истёкший дедлайн — понятная ошибка; повторный вход продолжает попытку или открывает результат без повторного учёта |
| UC06 | Ответы в чате | Вопрос → ответ (один вариант, несколько вариантов или текст) → сохранение → проверка → объяснение → следующий вопрос | Пустой ответ не отправляется; при ожидании ИИ видно состояние обработки; сбой сети или ИИ сохраняет подтверждённый прогресс; ошибка ИИ ≠ неверный ответ |
| UC07 | Отзыв и завершение | Заполнение и отправка отзыва → попытка «Завершена» → итоговая справка; счётчик завершивших +1 один раз | Закрытие формы без отправки не завершает опрос; при ошибке сохранения отправку можно повторить; поля — `[P04]` |
| UC08 | Мониторинг, закрытие, аналитика | Счётчик завершивших обновляется без перезагрузки страницы → закрытие вручную или по дедлайну → посещаемость, средний уровень понимания, два саммари | Нет завершённых попыток — нулевой счётчик и «Недостаточно данных» вместо выдуманной аналитики; ошибка одного саммари не скрывает второе и уже рассчитанные показатели |
| UC09 | Диалог и комментарий преподавателя | Список диалогов → комментарий в конец диалога с указанием авторства → push студенту → студент читает комментарий | Push запрещён или не доставлен — комментарий доступен в истории; повтор запроса не создаёт второй комментарий; push не раскрывает ответы и текст отзыва |
| UC10 | История и справка | Список пройденных опросов → вопросы, свои ответы, объяснения, итоговая справка, комментарий преподавателя | Пустая история — отдельное состояние; чужая попытка недоступна; история восстанавливается после повторного входа и перезапуска сервера |
| UC11 | Сбой сети или внешнего сервиса | Сообщение о проблеме, сохранённое состояние отделено от ожидающего отправки → после восстановления продолжение с подтверждённого места | Повторные запросы не дублируют ответ, отзыв, комментарий и счётчик завершивших; при недоступности LLM результат не выдумывается; действия после закрытия — `[P06]` |

## 9. Функциональные требования

42 требования с исходными ID; колонка «Проверяемый результат» описывает наблюдаемое поведение, по которому требование принимается. Метки `[P0x]` применяются после согласования соответствующего пункта §13.

### 9.1. Авторизация

| ID | Требование | Проверяемый результат |
|---|---|---|
| AUTH-1 | Регистрация по email и паролю с выбором одной роли (студент / преподаватель) | Создан один аккаунт с выбранной ролью; некорректные данные и повторный email аккаунт не создают |
| AUTH-2 | Вход по email и паролю | Корректные данные открывают интерфейс своей роли, неверные данные доступа не дают |
| AUTH-3 | Выход из аккаунта | Сеанс завершён, защищённые данные снова требуют входа |
| AUTH-4 | Восстановление пароля через email | После подтверждения работает новый пароль, старый не подходит |
| AUTH-5 | Хранение пароля в виде хеша | В БД и журналах нет открытого пароля; способ хеширования выбран при проектировании |

### 9.2. Лекции (преподаватель)

| ID | Требование | Проверяемый результат |
|---|---|---|
| T-LEC-1 | Создание лекции: название, дата, необязательное описание | Лекция сохранена с автором и видна в его списке; описание может быть пустым |
| T-LEC-2 | Редактирование и удаление лекции | Автор меняет и удаляет свою лекцию; чужому недоступно; данные с ответами — `[P08]` |
| T-LEC-3 | Прикрепление материалов: текст | Текст связан с лекцией и передаётся в генерацию вопросов |
| T-LEC-4 | Просмотр списка своих лекций | Видны только свои лекции |

### 9.3. Настройка опроса (преподаватель)

| ID | Требование | Проверяемый результат |
|---|---|---|
| T-QUIZ-1 | Настройка количества вопросов | Сохранено положительное целое; студент получает ровно столько вопросов; диапазон — `[P04]` |
| T-QUIZ-2 | Выбор типов вопросов: один вариант, несколько вариантов, короткий развёрнутый ответ | В наборе только разрешённые преподавателем типы |
| T-QUIZ-3 | Необязательная текстовая инструкция для ИИ | Пустая и заполненная инструкция сохраняются; заполненная передаётся при генерации |
| T-QUIZ-4 | Настройка дедлайна прохождения | Дедлайн сохранён и виден пользователям; после него новая попытка не начинается; начатые — `[P06]` |
| T-QUIZ-5 | Генерация кода доступа к опросу | Код ведёт к нужному опросу и не совпадает с кодом другого одновременно доступного опроса |
| T-QUIZ-6 | Ручное открытие и закрытие опроса | Открытый опрос доступен по коду; закрытый не принимает новые попытки; поведение начатых — `[P06]` |

### 9.4. Аналитика и диалоги (преподаватель)

| ID | Требование | Проверяемый результат |
|---|---|---|
| T-AN-1 | Просмотр количества студентов, завершивших опрос, в реальном времени | Счётчик обновляется без перезагрузки, учитывает каждого завершившего один раз и не включает попытки без отзыва; задержка — `[P09]` |
| T-AN-2 | ИИ-саммари по ответам студентов на вопросы лекции | Показаны общие результаты понимания и трудные аспекты, подтверждаемые ответами |
| T-AN-3 | Список диалогов студентов с ИИ-ботом | Преподаватель открывает диалоги только по своим лекциям |
| T-AN-4 | ИИ-саммари обратной связи о лекции | Саммари отражает отзывы отдельно от правильности ответов; доступ к отдельным отзывам — `[P02]` |
| T-AN-5 | Базовые графики: посещаемость, средний уровень понимания | Графики соответствуют данным и методике `[P01]`, `[P07]`; отсутствие данных не показывается как нулевое понимание |
| T-AN-6 | Добавление комментария преподавателя в конец диалога студента | Комментарий сохранён, виден в конце нужного диалога и отличим от сообщения ИИ |

### 9.5. Действия студента

| ID | Требование | Проверяемый результат |
|---|---|---|
| S-JOIN-1 | Вход в опрос по коду доступа | Код открытого опроса приводит к нужной лекции; неверный код и закрытый опрос дают понятную ошибку |
| S-JOIN-2 | Просмотр истории пройденных опросов | Студент видит список своих завершённых опросов и открывает связанные диалоги |
| S-CHAT-1 | Чат-интерфейс с ИИ-ботом (сообщения, вопросы, ответы) | Порядок сообщений сохранён; вопрос, ответ студента и объяснение ИИ явно различаются |
| S-CHAT-2 | Ответ на вопрос в формате теста (один или несколько вариантов) | Одиночный выбор принимает один вариант, множественный — набор; формат соответствует типу вопроса |
| S-CHAT-3 | Ответ на вопрос в формате короткого текста | Непустой текст сохраняется и передаётся на смысловую проверку |
| S-CHAT-4 | Получение мгновенной обратной связи после ответа | Объяснение к конкретному ответу показано до следующего вопроса; предел ожидания — `[P03]` |
| S-FB-1 | Заполнение обратной связи о лекции | Отзыв сохраняется для нужной попытки и лекции; поля и обязательность — `[P04]` |
| S-FB-2 | Без прохождения блока обратной связи опрос не считается завершённым | Без отправленного отзыва статус остаётся незавершённым; успешная отправка завершает попытку один раз |
| S-RES-1 | Просмотр итоговой справки по результатам опроса | После завершения доступны результаты и пояснения без учебной отметки |
| S-HIST-1 | Просмотр истории своих диалогов по лекциям | Повторное открытие показывает сохранённые вопросы, ответы и пояснения; чужой диалог недоступен |
| S-COMM-1 | Просмотр комментария преподавателя в конце диалога | Студент видит относящийся к нему комментарий, даже если push не был доставлен |

> S-JOIN-2 и S-HIST-1 частично пересекаются: первый — вход из списка опросов, второй — содержимое выбранного диалога. Оба ID сохранены.

### 9.6. ИИ-модуль

| ID | Требование | Проверяемый результат |
|---|---|---|
| AI-1 | Генерация вопросов по материалам лекции через внешний LLM API | Количество и типы соответствуют настройкам; вопрос обосновывается материалом; неполный или неверный формат не выдаётся как готовый набор |
| AI-2 | Уникальный набор вопросов для каждого студента (или случайная выборка из пула) | Набор закреплён за попыткой и не меняется при возврате; вариант индивидуальности — `[P05]` |
| AI-3 | Проверка коротких развёрнутых ответов по смыслу, а не по шаблону | Смысловой эквивалент распознаётся без дословного совпадения; ответ, противоречащий материалу, не считается правильным |
| AI-4 | Формирование мгновенной обратной связи студенту | Пояснение по материалу к конкретному ответу; сбой сервиса не подменяется неверной оценкой |
| AI-5 | Два ИИ-саммари для преподавателя: по ответам на вопросы лекции и по обратной связи о лекции | Сводки раздельные; при отсутствии данных нет вымышленных выводов |

### 9.7. Бэкенд и сетевые функции

| ID | Требование | Проверяемый результат |
|---|---|---|
| BE-1 | REST API для мобильного приложения и веб-версии | Оба клиента используют согласованные операции; коды ответов документированы |
| BE-2 | Хранение пользователей, лекций, материалов, вопросов, ответов, диалогов, обратной связи | Данные доступны после перезапуска; связи лекция — участник — результат не теряются |
| BE-3 | Аутентификация по токену | Защищённые операции требуют действительного токена; отсутствующий, неверный или истёкший токен доступа не даёт |
| BE-4 | Разграничение доступа по ролям | Студент не выполняет операции преподавателя; проверяется принадлежность лекции и диалога |
| BE-5 | Push-уведомление студенту при добавлении комментария преподавателя в его диалог | Уведомление сформировано нужному студенту; сбой доставки не отменяет комментарий |

Коды API: `200` успех, `400` неверные данные, `401` нет аутентификации, `403` запрет доступа, `404` ресурс не найден, `500` внутренняя ошибка. Точные пути (кроме `/login`) и дополнительные стандартные коды определяются в спецификации API. Скрытие существования чужого объекта через `404` допустимо при единообразной политике.

## 12. Данные, приватность, риски

**Сущности предметной области** (перечень, а не готовая ER-модель): аккаунт и роль, лекция и её автор, текстовые материалы, параметры опроса, набор вопросов попытки, ответы, сообщения диалога, отзыв, комментарий преподавателя, результат прохождения.

**Приватность.** Реальные персональные данные не используются. В LLM передаются только поля, необходимые для конкретной операции; email, токены входа и внутренние секреты в запрос к модели не включаются. Тексты ответов и отзывов сами могут содержать персональные сведения, поэтому состав передаваемых полей, сроки хранения и требования к провайдеру уточняются при проектировании безопасности. Полная анонимность отзывов не обещается до согласования `[P02]`.

| Риск | Требуемое поведение |
|---|---|
| Код опроса передан человеку вне аудитории | Показатель участия не выдаётся за доказательство присутствия; геолокация и проверка личности не добавляются без согласования |
| Вопрос или объяснение ИИ не опирается на лекцию | Проверка соответствия материалу и формата; ошибка генерации не выдаётся как готовый результат |
| В материале или ответе есть инструкция сменить правила ИИ | Пользовательский текст обрабатывается как данные; системные правила не меняются, чужие сведения не раскрываются |
| Внешний сервис медленный или недоступен | Явное ожидание, безопасный повтор, сохранение прогресса; параметры ожидания — `[P03]` |
| Повтор запроса создаёт вторую запись | Сервер сохраняет один результат логического действия; счётчики не увеличиваются повторно |
| Изменение или удаление лекции ломает историю | Выданные вопросы и результаты не переписываются незаметно; удаление по `[P08]` |
